# Session posts

One file per working session: `YYYY-MM-DD-<slug>.md`.

This is a **learning log**, not a changelog. `git log` already records what
changed. These record *how we got there* — the reasoning, the options weighed,
the things tried and dropped — so the architecture decisions stay legible
months later and the pattern is reusable.

## Shape

```markdown
# YYYY-MM-DD — <title>

**In one line:** <what this session was about>

## What we set out to do
<the goal at the start, and anything that changed mid-session and why>

## What we built
<the concrete output — files, services, decisions locked in>

## Dwayne's approach
<his calls and direction. The constraints he set. The questions he pushed on
that changed the outcome. Where his instinct differed from the first proposal.>

## Claude's approach
<the design choices and why. Options considered and rejected. Trade-offs
accepted. Where the plan was wrong and got corrected.>

## What we learned
<the transferable bit — the pattern, the gotcha, the mental model>

## Open threads
<what's unfinished, what the next session should pick up>
```

Keep it honest. "We spent an hour on the wrong theory" is more useful than a
tidy narrative.
